# termsprawl — Full Audit Report + Action Plan

*This is a maintainer self-review, not an independent assessment: the same
person wrote the code and this audit. It is a dated snapshot, kept for the
record. See [PROJECT-HEALTH.md](PROJECT-HEALTH.md) for how it should be read.*

**Date:** 2026-08-29 · **Baseline:** main @ 253f74f (v0.11.0 shipped), 580 tests green
**Scope:** frontend (renderer/nodes/components/styles), backend (main/core/server/relay), infra (CI, packaging, docs). Every finding below was verified against the code, not assumed.

---

## PART 1 — BACKEND / SECURITY FINDINGS

### B1. [CRITICAL] Server Edition: unauthenticated WS can execute arbitrary commands and exfiltrate secrets
`src/server/index.ts` accepts **any** WebSocket connection on `/ws` with no auth, and `buildHandlers` exposes the full IPC surface. Concretely, an unauthenticated client can:
- `pty:create` with `command: '<anything>'` → **arbitrary command execution** (`src/core/pty-manager.ts:55` accepts `req.command` and spawns it)
- `app:settings-get` → **reads chat API keys, Telegram token in plaintext** (`src/server/handlers.ts:91` returns full `loadAppSettings()`)
- `file:read` → **reads ANY path on the box** (`src/server/handlers.ts:155` — unlike desktop's project-confined file-service; `file:write` at :164 writes anywhere too)
- `git:*` → `resolveRepoRoot()` at :326 checks only `existsSync(cwd)` — **any repo on the machine**, not just known projects (desktop's `resolveGitTarget` at `src/main/index.ts:486` validates against known projects; the server copy doesn't)

PLAN.md's own risk note (line 983: "single-user scrypt + httpOnly cookie + origin check; never expose the box") was **never implemented**. It currently listens on `0.0.0.0` (no host arg to `server.listen`), so it's reachable from the LAN the moment someone runs it.

**Fix (1 day):** token auth on the WS handshake (random token printed once at boot, checked on upgrade), bind `127.0.0.1` by default with `RELAY_BIND`-style opt-out, route `file:read/write` + `git:*` + `pty:create` through the same known-project validators the desktop main uses (extract them to core so both share one implementation), and redact `chat.keys`/`telegram.token` from `appSettingsGet` responses.

### B2. [HIGH] `settings.get` returns provider keys + Telegram token to the renderer wholesale
Desktop renderer is trusted code, so this is only a hardening issue there — but the same shape is what makes B1 leak. Redact keys at the boundary (`appSettingsGet` returns `chat.keys` as `[{providerId, hasKey: true}]`) and have the settings panel send key *writes* through a dedicated channel that never echoes the secret back. Also remove the `slice(-4)`-of-secret hints or keep — they're benign, but the full-key return is not.

### B3. [MED] Chat tool-loop is wired but unusable end-to-end
`runChatLoop` accepts `tools: ChatToolDef[]` and the approval plumbing works (tested), but `src/core/chat/runtime.ts:116` passes `[]` — no tool definitions exist anywhere, and the OpenAI adapter (`toOpenAiMessages`, `src/core/chat/openai.ts:33`) **drops `assistant.toolCalls` when replaying history**, so even a future toolflow would break on the second provider turn (OpenAI requires the `tool_calls` field on the assistant message that initiated them). The ChatNode also renders tool results as plain text, not the promised permission cards.
**Fix (2–3 days):** add `toolCalls` to the OpenAI wire mapping + Anthropic `tool_use` blocks; register a first tool set (e.g. `read_file`, `list_dir` scoped to the project); render pending-approval cards in ChatNode with Approve/Deny buttons calling `chat.approve`.

### B4. [MED] Cost meter built but never connected
`src/core/chat/cost.ts` (tested) + `AppSettings.chat.priceOverrides` exist, yet neither ChatNode nor runtime imports it. The node shows a token chip only; the advertised cost chip shows nothing. The `/cost` slash command writes a **system-role message into the transcript** which is then sent to the provider on the next turn (OpenAI tolerates mid-conversation `system`; **Anthropic silently drops it**) — so `/cost` notes can vanish from model context in a provider-dependent way.
**Fix (0.5 day):** compute `{usd, estimated}` on each `usage` event in ChatNode via `conversationCost()` + settings overrides, render in the chip; make `/cost` a local-only annotation (new `role: 'note'` excluded from the wire mapping, like `stopped`).

### B5. [MED] Chat history is uncapped in node data
The 200 KB pair-dropping `serializeConversation()` exists and is tested, but `serializeNodes()` (`src/renderer/src/state/workspace.ts:522`) spreads `data` verbatim — a long-running chat writes an ever-growing transcript into `project.json`, breaking the git-shareable-projects promise (PLAN Phase 5).
**Fix (0.5 day):** apply the cap when persisting chat nodes (cap inside `serializeNodes` for `kind === 'chat'`, or have ChatNode commit through `serializeConversation`).

### B6. [MED] Chat wire mapping leaks local-only state
`stopped` messages go over the wire as normal assistant content (harmless but noisy); mid-conversation `system` notes (above) hit providers that mishandle them; there is no `max_tokens`/temperature control surfaced. Group under one "wire hygiene" pass with B3.

### B7. [MED] Relay runtime never disconnects on app quit + no renderer surface
`before-quit` (`src/main/index.ts:1055`) stops PTY/telegram/facade but **not** `relayRuntime` — a paired relay socket stays open during shutdown. Also `relay:connect/status` are registered in main but have **no preload/env.d.ts surface** and no Settings UI: the seam is unreachable from the app (by design for now, but it means `AppSettings.relay` is a dead knob). `relay:frame` broadcasts decrypted plaintext to a channel no renderer listens to — dead channel that still pushes data every frame; either wire it or gate it behind a subscription.

### B8. [LOW] Hook server accepts unauthenticated POSTs (loopback only)
`src/core/hook-server.ts` binds 127.0.0.1 and fail-opens by design — any local process can spoof agent status events. Acceptable local threat model, but worth a shared-secret header for defense-in-depth.

### B9. [LOW] Main window has no `setWindowOpenHandler`
Only webview guests deny popups (`src/main/browser/manager.ts:102`). A renderer `window.open` (or a compromised renderer) opens a new Electron window carrying the full preload. Add `setWindowOpenHandler(() => ({action: 'deny'}))` + route legitimate external links through `openExternal` (which already validates http/https at `src/main/index.ts:835`).

### B10. [LOW] Relay invite codes default `maxUses=1` but the hub defaults login to the invite code
Client identity = `client:<inviteCode>` when no login is sent (observed live). Two clients can never share an identity and revoked-invite history leaks into ids. Cosmetic/protocol-cleanliness; fix when adding the pairing UI.

### B11. [LOW] `termsprawl-file://` protocol serves any image on disk
`registerFileProtocol` (`src/main/index.ts:764`) validates only "is an image extension", not "is inside a known project". Renderer-compromise read primitive for images; fine for the desktop threat model, but don't port it to Server Edition as-is.

## PART 2 — FRONTEND / DESIGN FINDINGS

### F1. [HIGH] Light theme is a coat of paint over a dark app
`html[data-theme='light']` overrides 5 CSS variables and has just **2 light-specific rules**, but the stylesheet carries **26 hardcoded dark values** (`rgba(16,18,20,…)`, `#10110d`, `rgba(0,0,0,0.3)`) in node bodies, chat transcript, help pop, tab bar overlays. Switching to light leaves chat nodes, sticky headers, help popovers and toasts dark-on-dark. The theme setting is user-facing; this is a visible half-feature.
**Fix (1–2 days):** sweep all hardcoded darks into CSS variables (`--node-bg`, `--overlay-bg`, …), give light values, delete the two remaining `!important` hacks on `.react-flow__controls` where possible.

### F2. [HIGH] Language selector offers 5 languages with zero i18n behind it
Settings → General shows English/Deutsch/Español/Français/日本語 (`AppSettingsPanel.tsx:43`). Choosing any non-English does nothing — no locale dirs, no message catalogs. A dead control that silently lies.
**Fix:** either hide the control behind a "coming soon" state or wire `src/renderer/src/locales/` with at least the chrome strings. (Documented as cosmetic in types, but the UI presents it as functional.)

### F3. [MED] Accessibility gaps concentrated in the newest UI
- **6 `<select>`s in settings have no labels** (`aria-label`/`htmlFor` absent — `AppSettingsPanel.tsx:329/345/360/…`): screen readers announce nothing. Same pattern for the new Chat models rows.
- **Only 1 `:focus-visible` rule** exists app-wide (help-badge); inputs use `outline: none` with border-color change only (`styles.css:772,952,1161`) — keyboard focus is nearly invisible on unfocused-input patterns.
- **No `prefers-reduced-motion` guard** on the two infinite pulse animations (`chat-pulse`, `unread-pulse`).
- **`chat-usage` text at rgba 0.4 fails WCAG AA** (computed contrast 3.35:1 vs 4.5 required).
- ChatNode transcript/`<details>` thinking blocks have no aria-live region — streaming text is silent to screen readers.
**Fix (1 day):** label all selects (visible labels already exist as the copy column — wire `aria-labelledby`), add a global `:focus-visible` ring, wrap animations in the media query, bump `.chat-usage` alpha to 0.6+.

### F4. [MED] ChatNode UX gaps shipped with v0.11.0
- No error retry affordance: a failed send (B1-style errors, network) sets `error` text but leaves the user's message stranded in the transcript with no resend.
- No auto-scroll-on-user-scroll suppression: the effect pins scrollTop on every render (`ChatNode.tsx`), so a user scrolling up to read history gets yanked back down on the next token.
- `/cost` and token chip read only `data.messages` — the in-flight streaming message's usage isn't reflected until `done`.
- Slash commands are invisible: no autocomplete/menu (plan promised "minimal autocomplete").
**Fix (1 day):** scroll-follow only when already at bottom; add a retry button on error rows; autocomplete list for `/` prefixes.

### F5. [MED] z-index taxonomy is ad hoc
18 scattered z-index values from 3 to 4000 (help-pop 4000, banner 2000, toast 1000, overlays 450–500). Two overlays at 500 collide; help pop is hand-tuned above everything. Works today; one new fixed overlay away from a regression.
**Fix (0.5 day):** define a 5-step scale as CSS vars (`--z-canvas`, `--z-overlay`, `--z-modal`, `--z-toast`, `--z-popover`) and migrate.

### F6. [LOW] Duplicated `ChatNodeData` type definitions
`src/shared/types.ts:286` and `src/renderer/src/state/workspace.ts:85` declare structurally-similar-but-diverging copies (`streaming` exists only in the workspace copy, comments differ). Drift risk every time chat data changes. Point `workspace.ts` at `@shared/types` (or re-export) and delete the copy.

### F7. [LOW] Bundle size / no code splitting
Main renderer bundle is 9.2 MB (+13 MB ts worker, 1.9 MB css worker — Monaco). No `React.lazy` anywhere: every node kind (incl. Monaco + webview) loads at boot. Desktop app on NVMe — acceptable today, but a `lazy()` split of Editor/Diff/Browser nodes would cut boot cost ~50% and is a one-line-per-node change with Suspense.

### F8. [LOW] No `beforeunload` flush of the 600 ms persistence debounce
Quit within 600 ms of the last node move loses that layout. Add a flush on `beforeunload`/`blur` in Canvas.

### F9. [LOW] Remaining `!important` uses (5) and `outline: none` (6) — see F1/F3; no `transition: all` found (good), tab order on canvas is React Flow default (nodes not focusable — acceptable for a spatial canvas, but document the keyboard model: Delete/Backspace + Ctrl+Z work only when canvas has focus).

## PART 3 — INFRA / CONSISTENCY FINDINGS

### I1. [MED] CI runs no originality check and no relay-install step
- `check-originality.sh` runs nowhere in CI (needs the fork checkout — acceptable, documented), but the README/AGENTS present it as a hard gate; record the exception in the CI docs.
- Relay tests import `ws` and pass in CI **only because** `ws` happens to be a root dependency (the Server Edition's). `relay/package.json` + its `pnpm-lock.yaml` are tracked but never installed by CI; if the root ever drops `ws`, relay tests break mysteriously. Add `pnpm install --dir relay` (or a lockfile-hoist note) to both workflows.

### I2. [LOW] `relay/pnpm-lock.yaml` + `relay/package.json` "test": "node --test" script is dead (tests run via root vitest). Either wire `pnpm --dir relay test` to vitest or drop the script.

### I3. [LOW] GitHub Actions PR #6 still unverified end-to-end (account-level Actions disabled). The release path is Gitea-proven, so this is queued, not blocking.

### I4. [LOW] Docs drift is currently zero (PLAN/FEATURES/README/skill updated at release) — keep the "update on ship" rule.

### Verified-clean areas (probed, no findings)
- CSP meta present and strict (`default-src 'self'`, workers blob:) in `index.html`; shim-injected Server Edition page inherits it
- `openExternal` validates http/https (`src/main/index.ts:835`)
- webview guests: preload stripped, sandbox+contextIsolation forced, popups denied, navigation policy pure+tested (Phase 13)
- `ssh.ts` quotes every argv element (multi-word safe, regression-tested); remote file paths root-confined (`resolveRemoteFileTarget`, `OUTSIDE` guard); server `fileList` has `safeResolve` traversal guard
- Chat settings normalize round-trips; empty-shape stable; secrets never written to project files
- Telegram bot: allowlist enforced, ANSI-sanitized panes, timers cleaned up in `stop()`
- No `window.confirm/alert` misuse (in-app dialogs), no `transition: all`, no TODO/FIXME debt markers, no stray listeners (all keydown/resize handlers cleaned up), no leftover process/port leaks from the verification runs
- Preload path `.mjs` reference correct; core electron-guard enforced by test; server never imports `../main` (guard test)
